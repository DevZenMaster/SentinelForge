# SentinelForge Threat Model

## 1. Threat Modeling Methodology

SentinelForge employs the **STRIDE** methodology (Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege) along with qualitative risk assessment:
- **Likelihood**: Low, Medium, High
- **Impact**: Low, Medium, High, Critical
- **Risk Level**: Qualitative composite (Critical, High, Medium, Low)

> [!IMPORTANT]
> Defensive engineering operates under realistic security assumptions. Zero risk does not exist. All mitigations are paired with acknowledged residual risks.

| **T-01** | **Credential Stuffing / Password Brute-Force** | `/api/v1/auth/login` | High | High | **High** | Argon2id password hashing, IP and username rate limiting, account lockout thresholds. | Distributed botnets rotating IPs could slowly test common passwords below rate thresholds. |
| **T-02** | **Session Hijacking / Replay** | Session Bearer Tokens / Cookies | High | Medium | **High** | Short token TTL, cryptographic signature (HS256/RS256), DB-tracked session revocation, Secure/HttpOnly/SameSite cookies. | Compromise of client endpoint or memory dump of browser could expose active token before expiration. |
| **T-03** | **Privilege Escalation** | Admin/Analyst Endpoints | Critical | Medium | **High** | Strict server-side RBAC dependencies (`require_permission`), role hierarchy, rejection of client role claims. | Logic bugs in newly added route decorators if not covered by regression tests. |
| **T-04** | **Insecure Direct Object Reference (IDOR)** | `/api/v1/alerts/{id}`, `/api/v1/incidents/{id}` | Medium | Medium | **Medium** | UUID primary keys instead of sequential integers, ownership & tenant/RBAC validation on fetch. | Knowing a UUID allows read access if the user holds generic `alerts.read` permission. |
| **T-05** | **SQL Injection** | Dynamic queries & event search filters | Critical | Low | **Medium** | 100% SQLAlchemy 2.0 ORM parameterized statements; strict typing; no raw string query concatenation. | Developer error if custom raw SQL queries are introduced in future extensions. |
| **T-06** | **Stored / Reflected XSS** | Analyst Dashboard (Event viewer, notes) | High | Medium | **Medium** | React default string escaping, Content Security Policy (CSP), HTML sanitization on analyst markdown notes. | DOM-based injection if third-party chart libraries improperly parse unsanitized SVG strings. |
| **T-07** | **Cross-Site Request Forgery (CSRF)** | State-changing API endpoints | Medium | Low | **Low** | Strict `SameSite=Lax/Strict` cookies and `Authorization: Bearer` token pattern immune to standard ambient browser CSRF. | Cross-origin vulnerabilities if CORS is misconfigured with `Access-Control-Allow-Origin: *`. |
| **T-08** | **Rate Limit Abuse / API DoS** | `/api/v1/events`, `/api/v1/auth/*` | High | High | **High** | Ingestion payload size limit (`MAX_EVENT_PAYLOAD_BYTES=1048576`, returns 413), sliding-window rate limiters (`EVENTS_RATE_LIMIT_PER_MINUTE=1000` with `Retry-After`), request timeouts. | Coordinated volumetric DDoS saturating the network link before reaching the application layer. |
| **T-09** | **Log Injection (CRLF / Log Tampering)** | Ingestion payloads, correlation headers | Medium | Medium | **Medium** | Incoming `X-Request-ID` sanitized against `^[a-zA-Z0-9_\-:.]{1,64}$`; structured JSON logging with raw payloads excluded from operational and audit logs. | Downstream log collector parsing errors if raw logs are inspected outside structured formats. |
| **T-10** | **Malicious / Corrupt Event Payloads** | Ingestion endpoint (`/api/v1/events`) | Medium | High | **Medium** | Strict Pydantic v2 validation (`extra='forbid'`, IP validation via `ipaddress` without DNS lookups, timezone-aware UTC timestamps with past/future bounds, port range 0-65535, controlled severity enum). | Syntactically valid events containing deceptive semantic indicators. |
| **T-11** | **Unauthorized Event Ingestion** | Ingestion endpoint (`/api/v1/events`) | High | High | **High** | Requires authenticated session/Bearer token possessing `events.create` permission (`ADMIN` or `ANALYST`); `VIEWER` strictly denied with `403 Forbidden`; anonymous access denied with `401 Unauthorized`. | Compromise of an active analyst session allows an attacker to inject fraudulent events. |
| **T-12** | **Audit Log Tampering** | Audit log database table | High | Low | **Medium** | Append-only database table; absence of `UPDATE` or `DELETE` API endpoints for audit records; RBAC restrictions. | A compromised PostgreSQL superuser could directly mutate database records bypassing the API layer. |
| **T-13** | **Sensitive Data Disclosure** | API responses, stack traces | High | Low | **Medium** | Global exception handlers returning standardized error envelopes without stack traces; Pydantic response models excluding password hashes. | Verbose debug logging accidentally left enabled in production environment. |
| **T-14** | **Container / Host Compromise** | Docker container runtimes | Critical | Low | **Medium** | Non-root container execution (`USER nonroot`), minimal base images (Alpine/Distroless), read-only root filesystems where practical. | Zero-day kernel container escape vulnerabilities. |
| **T-15** | **Supply Chain Vulnerabilities** | Python/Node dependencies | High | Medium | **High** | Automated dependency scanning (`pip-audit`, Trivy, Dependabot), pinning exact versions, minimal dependency footprints. | Zero-day vulnerabilities in transitive dependencies prior to CVE disclosure. |
| **T-16** | **Secret Exposure** | Source control & Git history | Critical | Low | **Medium** | Strict `.gitignore`, pre-commit hooks, automated Gitleaks scanning in CI pipeline, zero hardcoded secrets. | Accidental commit of an active API key or `.env` file if developers bypass pre-commit hooks. |
| **T-17** | **Event Duplication / Replay Attacks** | Ingestion endpoint (`/api/v1/events`) | Medium | High | **Medium** | Idempotency enforced via `external_event_id` and `Idempotency-Key` header; database unique index; in-process lock preventing race conditions; duplicate returns 200 OK duplicate without re-inserting. | High-frequency client retries without idempotency keys create separate event entries. |
| **T-18** | **Parser DoS & Memory Exhaustion** | Normalization Dispatcher & Middleware | High | Medium | **Medium** | Streaming body size limit (413 on chunked/missing Content-Length > 1MB); JSON nesting recursion guard (max depth 8, returns 422); bounded non-backtracking regexes; graceful parser exception containment. | Malformed or adversarial payload crafted to cause parser crashes is contained as `FAILED` status without losing the raw event. |
| **T-19** | **Evidentiary Tampering & Evidence Mutation** | Normalization Pipeline | Critical | Low | **High** | Deepcopy payload isolation during normalization; post-parse immutability assertion; canonical attributes stored in dedicated columns and `attributes` JSONB, keeping `raw_payload` immutable. | Rogue parser code modifying dictionary keys in place is caught and restored from defensive copy. |
| **T-20** | **Unauthorized Incident Closure / Premature Case Dismissal** | `/api/v1/incidents/{id}/status` | High | Medium | **High** | Dedicated `incidents.close` permission separation (`ADMIN` only by default); strict state machine validation (`OPEN -> IN_PROGRESS -> RESOLVED -> CLOSED`); mandatory resolution category and notes. | Rogue administrator closing cases without thorough peer review. |
| **T-21** | **Forensic Evidence Deletion via Foreign Key Cascades** | `events`, `incident_events` tables | Critical | Low | **High** | Direct event links use `ForeignKey("events.id", ondelete="RESTRICT")`; database blocks deletion of raw events linked to active incidents or alerts; raw payloads remain strictly immutable. | Direct manual database truncation by PostgreSQL superuser. |
| **T-22** | **Analyst Impersonation & Note Forgery** | `/api/v1/incidents/{id}/notes` | High | Low | **Medium** | Note author attributed strictly from verified server session (`current_user.id`), not client payload; append-only notes; note body omitted from audit logs to protect investigation details. | Compromised analyst session token allows submitting notes under that analyst's identity until session revoked. |
| **T-23** | **Investigation Timeline Spoofing / Chronology Tampering** | `/api/v1/incidents/{id}/timeline` | Medium | Low | **Low** | Timeline engine strictly separates telemetric occurrence timestamps (`occurred_at`) from operational triage and analyst action timestamps (`action_at`). | System clock drift on un-synchronized distributed ingestion nodes. |

| **T-25** | **Server-Side Request Forgery (SSRF) via Indicator References** | Indicator URLs, domains, and external source references | Critical | Low | **High** | Strict architectural ban on outbound network calls: no automatic DNS resolution, reverse DNS, WHOIS, HTTP scraping, or payload fetching. Indicators are stored purely as passive evidence tokens. URL normalization strips embedded credentials and normalizes paths without initiating any external socket connections. | Analysts manually copying external advisory links and browsing them from internal workstations without network isolation. |
| **T-26** | **Credential Exposure via Embedded URLs in Indicators** | Ingested URLs and event telemetry containing embedded userinfo | High | Medium | **Medium** | Deterministic URL normalization explicitly strips userinfo (`username:password@`) before canonical storage and indexing; audit log values record only sanitized indicators; raw credentials never persist to indicator catalog or index tables. | The immutable raw event payload in `events.raw_payload` retains the original verbatim string for forensic chain-of-custody, requiring restricted access to raw event inspection. |
| **T-27** | **Investigation Data Leakage / Over-Fetching of Sensitive Telemetry** | `/api/v1/investigations/*` | Medium | Medium | **Medium** | Bounded event summaries (`InvestigationEventSummary`) omit `raw_payload` by default; strict Pydantic serialization models; password hashes, tokens, and internal credentials excluded from all response payloads. | Telemetry message bodies may contain sensitive business context necessitating analyst role verification. |
| **T-28** | **Correlation Graph Explosion & Memory Exhaustion DoS** | `/api/v1/investigations/context`, `/api/v1/investigations/timeline` | High | Medium | **High** | Strict query bounding and pagination across every dimension; max 500 events, max 200 alerts, max 100 incidents, max 200 indicators per query; subqueries and joins limit traversal depth to immediate incident/alert/event/indicator relationships without unbounded recursion. | High-frequency concurrent complex investigations could consume database connection pool capacity. |
| **T-29** | **Unauthorized Cross-Entity Pivot / IDOR via Correlation Traversal** | `/api/v1/investigations/*` | High | Low | **Medium** | Mandatory anchor resolution validating object existence and tenant/role boundaries; permission requirement (`investigations.read` enforced across ADMIN, ANALYST, VIEWER); non-existent or inaccessible entities return 404 cleanly without leaking existence. | Authorized users can correlate security telemetry within the boundaries of their SIEM role. |
| **T-30** | **Unbounded Historical Query DoS / CPU Starvation** | `/api/v1/investigations/context`, `/api/v1/investigations/events` | High | Medium | **High** | Mandatory anchor requirement (empty requests rejected with 422); hard temporal window limit (`MAX_INVESTIGATION_WINDOW_SECONDS = 2592000` / 30 days); compound indexes on `(source_ip, timestamp)`, `(destination_ip, timestamp)`, `(username, timestamp)`. | Multiple analysts querying 30-day windows simultaneously on high-volume sensors may increase query latencies. |
| **T-31** | **Temporal Attribution Confusion / Timestamp Manipulation** | `/api/v1/investigations/timeline`, `/api/v1/investigations/summary` | Medium | Low | **Low** | Strict semantic separation of telemetric occurrence time (`occurred_at`) from operational ingestion/action time (`action_at`); timezone-aware UTC enforcement; deterministic secondary (`entity_type`) and tertiary (`entity_id`) ordering for identical timestamps. | Sensor clock skew on un-synchronized ingestion endpoints prior to receipt. |
| **T-32** | **Detection Rule Injection / Arbitrary Execution** | `/api/v1/detection-rules` | Critical | Low | **High** | Strictly bounded declarative JSON schema; zero arbitrary Python code, eval, exec, regex compilation, or raw SQL; all conditions evaluate only explicit whitelisted operators (`equals`, `contains`, `greater_than`, `in`, `distinct_count`). | Syntactically valid rule definition configured with ineffective detection thresholds. |
| **T-33** | **Unauthorized Rule Activation & Mutation** | `/api/v1/detection-rules/*` | High | Medium | **High** | Granular server-side RBAC (`detection_rules.activate`, `create`, `update`, `disable`, `deprecate`); VIEWER role denied mutation with 403; append-only audit logging recording actor and state changes. | Compromised analyst session token modifying draft rules before session revocation. |
| **T-34** | **Detection Logic Tampering & Historical Inconsistency** | `/api/v1/detection-rules/{id}/versions/{v}` | High | Low | **Medium** | Strict immutability of published rules (`ACTIVE`, `DISABLED`, `DEPRECATED`); updates rejected with 409 Conflict; modification requires branching a new version (`vN+1`). | PostgreSQL superuser directly editing historical database records bypassing application layer. |
| **T-35** | **Rule Version Confusion / Forensic Decoupling** | Alert generation and rule versioning | High | Low | **Medium** | Alerts store exact immutable `rule_id` and `rule_version` at detection time; promoting new rule version never modifies historical alerts; each version historically queryable. | Analyst misinterpreting alert context if historical rule catalog documentation is neglected. |
| **T-36** | **Detection Resource Exhaustion / Unbounded Scan DoS** | `/api/v1/detection-rules` (threshold, window) | High | Medium | **High** | Hard server-side bounds validation: `time_window_seconds <= 86400`, `threshold <= 10000`, max 10 condition filters, max 255 char values; `DetectionContext` bounds sliding window queries to max 1000 events. | Many active rules evaluating against heavy concurrent event ingestion bursts. |
| **T-37** | **Concurrent Rule State Race / Dual Active Desynchronization** | `/api/v1/detection-rules/{id}/versions/{v}/activate` | Medium | Medium | **Medium** | Database-enforced partial unique index `uq_detection_rules_rule_id_active` (`UNIQUE (rule_id) WHERE status = 'ACTIVE'`); atomic nested transaction deactivating prior active version before activating target. | Concurrent racing analysts receive concurrency conflict error and must retry operation. |
| **T-38** | **Alert State Manipulation** | `/api/v1/alerts/{id}/transition` | High | Medium | **High** | Strict server-side state machine (`ALLOWED_ALERT_TRANSITIONS`); invalid and same-state transitions rejected with 400 Bad Request; RBAC requirement (`alerts.triage`); mandatory resolution notes on resolve; append-only audit logging recording before/after state diff. | Rogue analyst prematurely resolving alerts without remediation documentation. |
| **T-39** | **Alert Assignment Abuse** | `/api/v1/alerts/{id}/assign` | Medium | Medium | **Medium** | Server-side validation that target user exists and is active; client claims rejected; RBAC requirement (`alerts.assign`); audit logging of assignments and unassignments; prevents assigning deactivated or unauthorized accounts. | Compromised analyst account assigning all alerts to a single analyst to disrupt SOC triage. |
| **T-40** | **Alert Suppression Abuse** | `/api/v1/alerts/{id}/suppress` | High | Medium | **High** | Suppression requires dedicated `alerts.suppress` permission; mandatory non-empty justification (`reason >= 5 chars`); bounded expiration enforcement (max 90 days in future); suppressed alerts remain queryable and are never deleted; full audit attribution. | Malicious insider suppressing legitimate threat alerts to evade detection during active breach. |
| **T-41** | **Analyst Note Injection (Stored XSS / Payloads)** | `/api/v1/alerts/{id}/notes` | High | Medium | **Medium** | Server-side HTML entity escaping (`html.escape`); length bounding (1 to 10,000 chars); author strictly bound to authenticated session (`current_user.id`); notes are append-only and cannot be modified or deleted. | Notes containing obfuscated markdown or links directing analysts to external phishing portals. |
| **T-42** | **Alert Data Exposure / IDOR** | `/api/v1/alerts/*` | Medium | Medium | **Medium** | UUID alert identifiers; server-side RBAC validation (`alerts.read`, `alerts.notes.read`); non-existent alerts return 404 without leaking operational existence; bounded pagination (max 500); internal DB implementation details excluded from envelopes. | Authorized viewer role inspecting alert metadata across permitted sensor telemetry. |
| **T-43** | **Alert Operation Race / Concurrent Lost Updates** | `/api/v1/alerts/{id}/*` | Medium | Medium | **Medium** | PostgreSQL row-level locking (`with_for_update`); optimistic concurrency control with monotonic `version` counter; atomic transactions; racing mutations receive `409 Conflict`. | High-frequency simultaneous analyst operations on identical alert during active critical incident. |
| **T-44** | **Historical Alert Tampering & Provenance Corruption** | Alert triage & state change APIs | Critical | Low | **High** | Immutable detection provenance (`rule_id`, `rule_version`, `first_seen`, `last_seen`, `dedup_key`); operational endpoints cannot modify triggering rule version or evidence associations; historical alerts permanently reflect detection-time rule definitions. | Direct manual database manipulation by privileged DB administrator. |

| **T-46** | **Stored / Reflected XSS in SOC Web UI** | Alert triage notes, raw event payloads, IOC values | High | Medium | **High** | React default text interpolation and string escaping (zero `dangerouslySetInnerHTML`); backend `html.escape` sanitation on note ingestion; Content Security Policy (CSP) headers blocking inline script execution. | Zero-day parser vulnerability in third-party syntax highlighters or charting libraries. |

| **T-48** | **Clickjacking / UI Redress Attacks** | Analyst dashboard and triage modal dialogs | High | Low | **Low** | Global `X-Frame-Options: DENY` and CSP `frame-ancestors 'none'` HTTP security headers blocking iframe embedding across all routes. | Legacy browsers failing to honor modern frame-ancestor directives. |
| **T-49** | **Session Token Exfiltration via JavaScript** | Browser runtime memory and client cookies | Critical | Low | **High** | Session cookies issued with strict `HttpOnly`, `SameSite=Lax`, and `Secure` attributes; tokens never exposed to client-side document.cookie or localStorage. | Physical compromise or memory scraper on analyst workstation. |

| **T-51** | **Concurrency Race / Lost Updates during Concurrent Triage** | `/api/v1/alerts/{id}/*` state transitions | Medium | Medium | **Medium** | Optimistic concurrency control using monotonic `version` field; backend row-level locking (`with_for_update`); HTTP 409 conflict detection with interactive UI reload prompts. | High-frequency conflicting updates requiring manual analyst conflict re-evaluation. |
| **T-52** | **Malicious IOC Auto-Execution / DNS Pre-fetching** | Threat intelligence URLs and domain observables | Critical | Low | **High** | Disabling browser prefetch and preload on indicator values; passive string rendering without hyperlinking active malicious targets; no outbound socket or DNS calls. | Analyst manually copying raw malicious URL into browser address bar without sandbox. |
| **T-53** | **Open Redirect via Authentication Flow** | `/login` post-authentication redirects | Medium | Low | **Low** | Relative path validation on post-login redirects; strict disallowance of external URI schemes (`javascript:`, `data:`, `//external.domain`). | Misinterpretation of complex relative URL path traversals. |
| **T-54** | **Sensitive Telemetry Exposure in Browser Cache / History** | Security events, payload dumps, and audit logs | Medium | Medium | **Medium** | HTTP headers `Cache-Control: no-store, no-cache, must-revalidate` on sensitive operational API responses; sensitive credential fields omitted in serialization. | Unlocked analyst workstation accessed by unauthorized personnel. |

| **T-59** | **SQL / Filter Parameter Injection** | `/api/v1/reports/*` query params | Critical | Low | **High** | 100% SQLAlchemy 2.0 ORM parameterized statements; strict Pydantic enum validation on report types, formats, and dates; zero raw SQL string concatenation. | Malformed query parameter inputs rejected with HTTP 422 before reaching database layer. |

| **T-63** | **Historical Rule Version Confusion & Provenance Loss** | Detection engineering reports | High | Low | **Medium** | Detection metrics group alerts strictly by detection-time `rule_id` and immutable `rule_version`; promoting new rule versions never alters historical alert associations; exact provenance preserved. | Rule deprecation or naming changes causing historical version documentation discrepancies. |
| **T-64** | **Compliance Metric Misrepresentation & Artificial Scoring** | `/api/v1/reports/compliance` | Medium | Low | **Medium** | Strictly objective evidence model mapping to factual database observations (`EVIDENCE_AVAILABLE` vs `EVIDENCE_MISSING`); zero subjective percentages, AI hallucinations, or unverified compliance certifications. | Auditor mistaking verifiable operational evidence for an external third-party compliance certification. |

| **T-74** | **Secret Leakage Through Logs, Errors & API Responses** | Application logs, stack traces, and API responses | Critical | Low | **High** | Recursive structured log sanitization (`JSONLogFormatter._sanitize`) redacting passwords, session tokens, API keys, and integration secrets; global DB error handler preventing raw SQL/connection string leakage; write-only integration secrets exposing only masked previews (`••••••••abcd`). | Debug-level application logging manually forced in production environment. |
| **T-75** | **Request Correlation Tampering & Log Injection** | `X-Request-ID` and `X-Correlation-ID` headers | Medium | High | **Medium** | Strict regex validation (`^[a-zA-Z0-9_\-:.]{1,64}$`); malformed or oversized IDs discarded and replaced with secure random identifiers (`req-<uuid>`); structured JSON formatting preventing CRLF log injection. | High-frequency client retries generating large volumes of unique request IDs. |
| **T-76** | **Database Connection Pool & Resource Starvation** | PostgreSQL database connection pool | High | Medium | **High** | Bounded connection pool sizing (`DB_POOL_SIZE`, `DB_MAX_OVERFLOW`, `DB_POOL_TIMEOUT`, `DB_POOL_RECYCLE`); automated session rollback on exception; `pool_pre_ping=True` detecting dropped connections; operational pool telemetry (`get_pool_status`). | Coordinated complex investigation queries saturating database CPU before reaching connection pool limits. |
| **T-77** | **Background Worker Crash & Stuck Delivery Reconciliation** | Notification background delivery tasks | High | Medium | **High** | Startup reconciliation (`reconcile_stale_deliveries`) sweeping deliveries left stuck in `DELIVERING` after process crash and safely rescheduling to `RETRYING` or `EXHAUSTED`; graceful shutdown draining in-flight tasks (10s bounded timeout). | Sudden hard container SIGKILL (OOM killer) terminating process before graceful shutdown handler executes. |
| **T-78** | **Supply-Chain Dependency Compromise & Lockfile Tampering** | Python and Node dependencies | High | Medium | **High** | Pure package-manager enforcement (`pnpm` only, removal of `package-lock.json`); automated CI dependency scanning, frozen lockfile builds (`pnpm install --frozen-lockfile`), pinning major versions, minimal base images. | Zero-day vulnerabilities in upstream open-source packages before CVE publication. |
| **T-79** | **Container Privilege Escalation & Insecure Runtimes** | Docker container runtimes (`api.Dockerfile`, `web.Dockerfile`) | Critical | Low | **High** | Multi-stage hardened builds executing strictly as non-root unprivileged service users (`USER sentinelforge:sentinelforge` UID 10001, `USER nextjs:nodejs` UID 1001); removal of compilers and build tools from final images; read-only container root filesystems where practical. | Zero-day kernel container escape vulnerabilities. |
| **T-80** | **Backup Corruption & Forensic Evidence Recovery Failure** | PostgreSQL backup dumps and restore procedures | Critical | Low | **High** | Automated, read-only recovery verification tool (`scripts/verify_backup_integrity.py`) validating presence and foreign-key integrity across all 21 evidentiary tables; encrypted GPG/AES-256 backup storage; documented DR restoration runbooks. | Undetected disk corruption on primary storage before scheduled backup execution. |
